# 策略开发工作流

## 目标

让每次策略变更都能回答三个问题：

1. 使用了哪些时点可获得的数据？
2. 在什么时点、以什么价格和成本成交？
3. 改善是否同时存在于风险、收益和样本外结果，而不是只存在于总收益？

## 变更前

1. 执行 `git status --short --branch`，保留用户已有改动和未跟踪文件。
2. 阅读根目录 `AGENTS.md`、`docs/repo_audit.md` 和 `docs/unknowns.md`。
3. 明确变更属于 JavaScript 雷达、V6、旧框架还是跨实现一致性。
4. 记录数据样本、配置、代码提交和成交模型。
5. 运行全部现有测试。
6. 策略相关变更必须运行基准回测并保存变更前指标。
7. 若规则为“待确认”，先请求确认，不得进入实现。

## 实现约束

- 先补充能够失败的测试，再修改策略实现。
- 因子只能引用当前及过去数据。
- T 日收盘信号不得赚取只有按 T 日收盘成交才能获得的收益。
- 参数放入对应配置文件，策略代码不得出现新的业务常量。
- 手续费、滑点、现金和无法成交规则必须在收益计算中明确体现。
- 组合构建后必须验证：
  - 每只 ETF 权重不超过限制
  - 总风险暴露不超过100%
  - 现金权重不为负
  - 缺失或无效因子不得入选

## 验证顺序

### 1. Node 测试

```bash
npm test
```

### 2. V6 Python 测试

```bash
cd etf-rotation-v6
python -m unittest discover -s tests -v
```

### 3. 旧框架 Python 测试

```bash
cd ETF-Quant-System
python -m unittest discover -s test -v
```

### 4. 基准回测

使用固定数据、固定配置和固定成交模型运行。不得在看到结果后修改参数并继续把同一段
数据称为样本外。

## 结果比较

策略变更至少比较：

- 年化收益
- 最大回撤
- 夏普
- 卡玛
- 换手率
- 样本外表现

同时报告数据区间、ETF池、成本、滑点和成交价格。不得仅报告表现改善的指标。

## 完成门禁

只有同时满足以下条件才可声称完成：

- 全部测试通过
- 基准回测成功
- 没有未解释的指标口径变化
- 没有新增未来函数或数据泄漏
- 没有泄露密钥或私人交易数据
- 所有待确认事项已明确保留或获得用户决定

任何测试失败、基准不可复现或规则未确认时，必须报告为未完成。
