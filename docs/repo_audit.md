# 仓库审计基线

审计日期：2026-07-31
基准提交：`a9b1a49 feat: initialize ETF quant project`
基准分支：`main`

## 审计范围

本审计覆盖根目录 JavaScript 应用、`etf-rotation-v6`、`ETF-Quant-System`、
现有测试和基准报告。审计只评价策略定义、数据时序、组合约束和测试覆盖，不评价参数
是否能够提高历史收益。

## 仓库组成

### 根目录 JavaScript 实时雷达

- `server.js`：行情获取、ETF 池、市场状态、组合保存和 HTTP 服务。
- `factors.js`：动量、路径效率、趋势、回撤、波动率、生命周期、建议和组合构建。
- `public/`：本地网页。
- `test/`：JavaScript 单元测试。

该实现面向实时扫描和组合建议，没有正式历史回测引擎。

### `etf-rotation-v6`

- `config/strategy_v6.yaml`：V6 参数。
- `src/`：因子、评分、市场状态、组合、风控和回测。
- `tests/`：V6 单元测试。
- `backtests/`：固定样例产生的基准结果。

该实现是独立的 Python 研究回测原型，不是 JavaScript 策略的逐项复刻。

### `ETF-Quant-System`

包含 V1、V1.2、优化轮动、基础回测和状态化回测。它与 V6 没有代码依赖，
当前应视为历史研究框架。是否继续维护为“待确认”。

## 已确认的主要风险

1. V6 将 T 日目标权重向后移动一行，但随后赚取 `close[T+1]/close[T]-1`，
   经济含义仍接近按 T 日收盘成交；正式执行价格“待确认”。
2. V6 横截面评分可能奖励暖机期缺失因子，配置中的 `minimum_history` 尚未生效。
3. V6 回撤冷却不重置高水位，达到阈值后可能反复进入冷却并永久保持现金。
4. V6 计入手续费，但没有滑点参数和滑点实现。
5. V6 当前配置限制总暴露不超过100%，但代码没有验证所有配置组合均满足该约束。
6. JavaScript 组合实际单只权重可能高于 `server.js` 展示的仓位原则。
7. `ETF-Quant-System/backtest/engine.py` 对零权重前向填充，可能保留已被调出的
   旧持仓并使总仓位超过100%。
8. 三套实现的因子窗口、路径效率方向、回撤定义、市场状态和组合构建均不一致。
9. 当前基准只使用短期人工样例，不能用于判断真实策略表现。
10. 根目录 `data/current-portfolio.json` 是未跟踪的私人运行时组合数据，其管理规则
    “待确认”。

## 已确认的公式差异

| 项目 | JavaScript | Python V6 |
|---|---|---|
| 动量 | 20/60/120日，跳过5日 | 3/5/10日，跳过1日 |
| 路径效率 | 有方向净位移/路径 | 绝对净位移/路径 |
| 回撤 | 窗口内最大路径回撤 | 当前价格距滚动高点 |
| 趋势 | MA20/MA60 | 个券评分中无均线趋势因子 |
| 流动性 | 20日成交额过滤 | 无 |
| 市场状态 | 指定指数与北证50 | 全池平均价格与市场宽度 |
| 组合 | 类别优先级与生命周期 | 评分前N名 |

## 当前测试缺口

- 信号日、成交日和收益归属的严格时序
- 手续费精确金额和扣费日期
- 滑点
- 回撤触发、冷却结束和重新入场
- 暖机期与缺失因子
- 所有市场状态下的总仓位和单只上限
- 已知净值路径的最大回撤
- 停牌、缺失日期、新上市、退市和历史池变化
- JavaScript 与 Python 因子一致性
- 样本外验证

## 审计结论

当前主要矛盾是“仓库已经包含多套可运行策略”与“尚未确定唯一策略规范”之间的冲突。
在成交时序、数据规则和唯一真源确认前，不应优化参数或使用基准收益评价策略。
