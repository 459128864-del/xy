审计更新：2026-08-01
审计范围：根目录JavaScript雷达、`etf-rotation-v6`、`ETF-Quant-System`、测试与研究文档。

## 实现所有权

| 实现 | 当前角色 | 可以声称的结果 |
|---|---|---|
| `etf-rotation-v6` | 唯一策略与回测真源 | V6工程、历史与样本外研究结果 |
| 根目录JavaScript | 独立实时雷达 | 当下扫描和独立模型建议，不得引用V6绩效 |

三套实现的因子和组合规则仍不相同，这是明确的产品边界，不再是未决的策略所有权。

## 公式差异

| 项目 | JavaScript雷达 | Python V6 |
|---|---|---|
| 动量 | 20/60/120日，跳过5日 | 3/5/10日，跳过1日 |
| 路径效率 | 有方向净位移/路径 | 绝对净位移/路径 |
| 回撤 | 窗口内最大路径回撤 | 当前价格距滚动高点 |
| 趋势 | MA20/MA60 | 个券评分无均线趋势因子 |

| 市场状态 | 3个日线宽基；北证50实时仅展示 | 全池趋势和宽度 |
| 组合 | 类别优先级与生命周期 | 评分前N名与配置暴露 |

## 已完成修复

### Python V6

- T日收盘信号在T+1收盘成交，新权重只影响T+1→T+2。
- 非调仓日权重自然漂移，现金显式保留；turnover基于成交前实际权重。
- 手续费和滑点分别记录，使用同一乘法净值会计口径。
- `minimum_history`按每只ETF自身历史生效，关键因子缺失时不得入选。
- 效率因子暖机期保持缺值；完整平坦路径明确为零效率。
- 原始行情不填充；停牌估值沿用最后收盘价、复牌计入完整变化，缺原始收盘价时禁止交易。
- `max_position`优先于目标暴露，受限后的剩余部分保留现金。
- 回撤冷却结束后允许重新入场，不再因旧高水位永久重复触发。
- 已实现真实ETF数据管道、沪深300Benchmark、滚动/扩展样本外和市场分段验证。

### JavaScript雷达

- 进攻、均衡、防守单只仓位分别不超过20%、15%、10%。
- 候选不足不再重新归一化并突破单只上限；小数权重不再逐项取整导致总暴露偏移。
- 未知状态保持100%现金。
- 北证50实时涨跌仅展示，不参与其他日线指标的状态投票。
- 首次扫描不再自动写入“当前组合”，只有显式采用操作才落盘。

### 历史框架

- 删除逐列零权重 `ffill`，空选券会在下一交易日收盘执行全现金。
- 统一为T日信号、T+1收盘成交。
- 非调仓日权重自然漂移，现金保留。
- 成本和返回净值采用同一乘法口径，不再维护相互矛盾的两条净值。

## 当前仍存在的研究边界

- 历史池工程链路已支持上市/退市生命周期、点时资格、退市行情覆盖和证据清单门禁；
  固定研究池仍未获得全量授权历史目录与行情，不能声称“已控制幸存者偏差”。
- 公开当前列表不能替代交易所历史上市/终止上市档案，完整目录仍需合法数据授权。
- 停牌期间估值、恢复交易、涨跌停、部分成交和成交量约束尚未形成正式规则。
- 前复权数据、手续费和滑点尚未经过生产级多数据源交叉校验与真实市场校准。
- JavaScript雷达没有与自身公式完全对应的历史回测，不能评价其历史有效性。
- V6最终留出期已经使用，不得继续用同一区间筛选参数。
- V6在熊市和完整区间的回撤仍高，不适合模拟盘或实盘。

## 测试门禁

- JavaScript覆盖因子、建议、各状态仓位上限、候选不足、未知状态和实时指标隔离。
- V6覆盖未来函数、T+1时序、漂移、现金、成本、台账、暖机、缺失行情、仓位限制、
  回撤重新入场、Benchmark、滚动窗口和单因素留出选择。
- 历史框架覆盖T+1收益归属、空选券清仓、自然漂移和净值会计一致性。

## 审计结论

历史审计中的成交时序、滑点、暖机、永久现金、JS仓位冲突、旧引擎 `ffill` 和双净值
问题已修复。当前主要矛盾已从“工程状态错误”转为“数据完整性和策略熊市有效性不足”。
在历史ETF池、停牌成交规则和新样本外数据补齐前，不进入模拟盘或实盘。
