## 配置与交易假设

- 调仓频率：每 5 个数据日期构造一次目标权重
- 标的数量：前 2 名
- 单只上限：50%
- 总仓位：市场状态目标为进攻 100%、均衡 70%、防守 35%；当前参数下组合构造会按目标敞口归一化且不超过 100%
- 市场状态：全标的平均价格相对 10 日均线判定趋势，以高于均线的标的比例和 55% 阈值区分进攻、均衡、防守
- 风控：组合回撤达到 8% 后空仓 5 日
- 手续费：换手率 × 0.0005，已从当日组合收益扣除
- 滑点：未配置、未计算
- 文档成交假设：T 日收盘生成信号，T+1 执行
- 代码实际含义：T 日目标权重 `shift(1)` 后乘以 T 到 T+1 的收盘收益，因此获得该完整区间收益需要在 T 日收盘成交；与文档和项目规则冲突

## 一致性与风险审计

- 因子计算未发现直接读取未来行，但现有无未来函数测试只覆盖动量因子。
- 成交时间存在明确错位，违反“T 日收盘信号最早 T+1 交易”规则。
- `rank(na_option="bottom")` 与“分位数越大越好”组合使用，可能使缺失因子获得偏高分；同时 `minimum_history` 未生效。
- 市场状态仓位确实传入 Python V6 组合构造；当前配置下总仓位和单只仓位受限。代码未对任意非法配置做完整校验。
- 回撤风控的历史峰值在冷静期后未重置，可能反复触发，预期行为待确认。
- JavaScript 与 Python 不是同一公式：动量窗口和跳过期不同；路径效率的正负定义不同；回撤定义不同；JavaScript 另含均线趋势、成交额/流动性、生命周期和品类优先级；市场状态定义也不同。
- JavaScript 版本没有完整回测、手续费和滑点链路，不能与 Python V6 的回测结果直接等价比较。

## 测试与可重复性

Node 5/5、Python V6 4/4、旧 Python 框架 1/1 均通过。两次独立回测的指标文件和净值曲线逐字节一致。现有测试缺少成交日、滑点、成本数值影响、完整链路无泄漏和逐笔交易统计覆盖。

- Node：`npm test`
- Python V6：`.venv/bin/python -m unittest discover -s tests -v`
- 旧 Python 框架：`../etf-rotation-v6/.venv/bin/python -m unittest discover -s test -v`

- 基准回测：`.venv/bin/python scripts/run_backtest.py`
